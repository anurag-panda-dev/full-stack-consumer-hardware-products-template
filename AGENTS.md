# AGENTS.md — AI agent context for this repository

Monorepo for **connected-hardware products**: hardware engineering + companion software + device cloud. Every folder has a `purpose.txt` — read it before writing anything there.

## Repository map

**Hardware:** `products/<line>/` (specs/variants/releases — links into disciplines) · `mechanical/` · `electronics/` · `firmware/` · `certification/` · `manufacturing/` · `supply-chain/` · `validation/` · `packaging/` · `test-tools/`

**Software:** `apps/` (thin shells: web, admin, mobile) · `crosscutting/device-sdk` · `kernel/` (design-system, contracts, auth, offline, i18n, entitlements, config) · `platform/` (api, ota, telemetry, notifications, payments, jobs, identity, database, observability) · `tests/`

**Shared:** `datasets/` · `content/` · `docs/` · `rfcs/` · `business/` · `legal/` · `labs/` · `sandbox/` · `infra/` · `tooling/` · `security/`

## Hard rules

1. Respect the import boundaries in `PACKAGE.md` — no app imports `platform/` internals; no software folder imports hardware artifacts or vice versa (protocol docs/contracts are the seam).
2. `kernel/contracts` is the single source of truth for data shapes — firmware message schemas and OTA manifests derive from it.
3. `logic/` stays framework-free (no React/HTTP/DB).
4. Artifacts live in discipline folders; `products/<line>/product.md` links them — never copy artifacts into product folders.
5. Generated files (Gerber/STEP exports, API clients, tokens) are regenerated by `tooling/` — never hand-edited.
6. Never pre-create empty folders; every new folder gets a `purpose.txt` (`PURPOSE:` / `SHOULD CONTAIN:` / `SEE:`).
7. Architecture/engineering changes need an RFC in `rfcs/` first, then an ADR from `docs/decisions/TEMPLATE.md`.
8. Secrets go in `.env` (never committed); `.env.example` documents keys.
9. Compliance claims require a linked standard number or lab report in `certification/`/`validation/`.
10. Corporate docs (equity, HR, signed contracts, IP filings) never enter this repo.
